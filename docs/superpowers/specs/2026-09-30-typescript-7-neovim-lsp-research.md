# TypeScript 7 LSP for Neovim

**Recommendation:** replace `vtsls` with the TypeScript 7 native server only for ordinary TypeScript/JavaScript projects. Install the stable `typescript` package and use the maintained `nvim-lspconfig` configuration named `tsc`; it launches `tsc --lsp --stdio`. Keep a TypeScript 6 / `vtsls` path for workspaces that require TypeScript language-service plugins or embedded-language tooling until those tools support TypeScript 7. [TypeScript 7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) · [nvim-lspconfig `tsc` implementation](https://github.com/neovim/nvim-lspconfig/blob/master/lsp/tsc.lua) No Neovim configuration was changed by this research.

## Server and protocol status

- TypeScript 7 is released on the standard `typescript` npm package. The package exposes the `tsc` executable, and Microsoft documents `npm install -D typescript` followed by `npx tsc`; the current npm `latest` metadata identifies version 7.0.2 and `tsc` as its only binary. Start its native language server over stdio with `tsc --lsp --stdio` (or `npx tsc --lsp --stdio` for a workspace install). [TypeScript 7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) · [npm registry metadata](https://registry.npmjs.org/typescript/latest)
- This is a real LSP server, not the legacy `tsserver` protocol: Microsoft says TypeScript 7's editor foundation is LSP and supports multithreaded request handling. The released server includes auto-imports, expandable hovers, inlay hints, code lenses, go-to-source-definition, JSX linked editing/tag completions, semantic highlighting, sort imports, and remove-unused-imports. [TypeScript 7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)
- The server is production-released, but TypeScript 7.0 deliberately has no stable programmatic API; Microsoft expects that API in 7.1. Consequently, tools that embed the compiler/language service—including Vue, MDX, Astro, Svelte, and Angular template workflows—must currently continue using TypeScript 6 for editor support. [TypeScript 7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)

## Direct Neovim integration

- Current `nvim-lspconfig` ships a `tsc` configuration specifically for TypeScript 7+. Its documented activation is `vim.lsp.enable('tsc')`; its implementation starts `{ tsc, '--lsp', '--stdio' }`, accepts JS/JSX/TS/TSX buffers, and declines to attach when it cannot find a binary with major version at least 7. It also avoids attaching to a nearer Deno workspace and resolves monorepo roots from package-manager lockfiles. [nvim-lspconfig `tsc` documentation](https://github.com/neovim/nvim-lspconfig/blob/master/doc/configs.txt) · [implementation](https://github.com/neovim/nvim-lspconfig/blob/master/lsp/tsc.lua)
- Therefore the implementation migration should select `servers = { tsc = {} }` through this repository's existing LazyVim/nvim-lspconfig integration, rather than adding another LSP framework. If configuring directly, Neovim's built-in client supports defining a `vim.lsp.config()` with `cmd = { 'tsc', '--lsp', '--stdio' }` and enabling it with `vim.lsp.enable()`; use the maintained `tsc` config where available because it supplies the TypeScript-aware binary, monorepo, and Deno handling. [Neovim LSP configuration documentation](https://neovim.io/doc/user/lsp.html) · [nvim-lspconfig `tsc` implementation](https://github.com/neovim/nvim-lspconfig/blob/master/lsp/tsc.lua)
- Do **not** substitute `ts_ls` or the deprecated `tsgo` config. `ts_ls` runs `typescript-language-server`, which wraps `tsserver`; its own nvim-lspconfig documentation currently requires TypeScript `< 7`. `tsgo` is deprecated in favour of `tsc`. [nvim-lspconfig `ts_ls` implementation](https://github.com/neovim/nvim-lspconfig/blob/master/lsp/ts_ls.lua) · [nvim-lspconfig configuration documentation](https://github.com/neovim/nvim-lspconfig/blob/master/doc/configs.txt)

## vtsls cutover implications

- `vtsls` is not TypeScript 7's LSP. It is an LSP wrapper around VS Code's TypeScript extension, starts as `vtsls --stdio`, and defaults to its bundled TypeScript/`tsserver`; its `vtsls.*` settings and TypeScript/VS Code extension commands are specific to that wrapper. The replacement is a server/protocol cutover, not a version bump inside `vtsls`. [vtsls README](https://github.com/yioneko/vtsls/blob/main/README.md) · [vtsls capabilities](https://github.com/yioneko/vtsls/blob/main/packages/server/src/capabilities.ts)
- Before removing `vtsls`, audit and replace any configuration or keymaps that invoke its custom commands (for example `typescript.tsserverRequest`, `typescript.selectTypeScriptVersion`, and `_typescript.configurePlugin`) or set `vtsls.*` options; those are documented vtsls/tsserver interfaces, not part of the TypeScript 7 native-server contract. Re-test project-wide source actions and refactors after the switch rather than assuming command-level compatibility. [vtsls README](https://github.com/yioneko/vtsls/blob/main/README.md)
- Pin TypeScript 7 at the workspace root (and use the same version across a monorepo) so the selected `tsc` is unambiguous. `nvim-lspconfig` intentionally skips a local pre-7 binary and falls back to a qualifying executable, which otherwise could make editor behavior differ by package. [nvim-lspconfig `tsc` implementation](https://github.com/neovim/nvim-lspconfig/blob/master/lsp/tsc.lua)
- Separately from the editor migration, TypeScript 7 changes some compiler defaults and removes several deprecated options. Validate each workspace's `tsconfig` and diagnostics during rollout; Microsoft specifically calls out `rootDir`, `types`, `baseUrl`, legacy module resolution, and ES5 support. [TypeScript 7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)

## Implementation checklist (for a follow-up configuration change)

1. Ensure each non-embedded TypeScript workspace has `typescript@^7` available, preferably at its monorepo root. [nvim-lspconfig `tsc` implementation](https://github.com/neovim/nvim-lspconfig/blob/master/lsp/tsc.lua)
2. Ensure the installed `nvim-lspconfig` revision contains the `tsc` configuration, then enable `tsc` through the existing LazyVim server table. [nvim-lspconfig `tsc` documentation](https://github.com/neovim/nvim-lspconfig/blob/master/doc/configs.txt)
3. Remove the Mason `vtsls` installation and all vtsls-specific configuration/keymaps only after the native server has been exercised in TypeScript and JavaScript projects. [vtsls README](https://github.com/yioneko/vtsls/blob/main/README.md)
4. Retain or deliberately route embedded-language/plugin workspaces to the TypeScript 6 path until their maintainers support TypeScript 7's new API. [TypeScript 7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)
