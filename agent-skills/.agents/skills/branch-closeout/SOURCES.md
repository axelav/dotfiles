# Sources and adaptation decisions

Research snapshot: 2026-10-13. These sources inform the workflow; they are not runtime dependencies or authorization to mutate GitHub. Source-local models, PostHog policies, credentials, paths, queues, and skill stores are deliberately not copied.

## Review and triage

- [PostHog: Stop being the code review bottleneck](https://posthog.com/newsletter/code-review-tips): independent reviewers; actionable/nit/ambiguous triage; bounded repair/re-review; delegate CI toil; observe real behavior instead of accepting reasoning as proof.
- [Paul D'Ambra: qa-swarm](https://github.com/pauldambra/dotfiles/blob/52479b39e045efd374f6d0d61b9514d979aa11a3/ai/skills/qa-swarm/SKILL.md): the inspected revision has a cheap-first router with conditional specialist delegation, not the article's fixed four-reviewer panel. The parent routes scopes and independent delegates return structured findings. Its inline GitHub publication and count-based verdict are not inherited.
- [Paul D'Ambra: review-triage](https://github.com/pauldambra/dotfiles/blob/52479b39e045efd374f6d0d61b9514d979aa11a3/ai/skills/review-triage/SKILL.md): explicit dispositions, scoped fixes, human-participation gate, and explained bot-thread resolution. This adaptation retains the dispositions/human boundary but leaves **all** threads untouched; its fixes must pass observed verification before publication.
- [Paul reviewer](https://github.com/pauldambra/dotfiles/blob/52479b39e045efd374f6d0d61b9514d979aa11a3/ai/skills/paul-reviewer/SKILL.md) and [XP reviewer](https://github.com/pauldambra/dotfiles/blob/52479b39e045efd374f6d0d61b9514d979aa11a3/ai/skills/xp-reviewer/SKILL.md): caller empathy, rollout/operational implications, meaningful contracts, simple design and requirement-proportional complexity. No Paul impersonation, speculative refactor mandate, or style-only blockers.
- [PostHog QA team](https://github.com/PostHog/posthog/blob/383f512776d845e9085d3b500ed6371f4fbe4ece/.agents/skills/qa-team/SKILL.md) and [security audit](https://github.com/PostHog/posthog/blob/383f512776d845e9085d3b500ed6371f4fbe4ece/.agents/skills/security-audit/SKILL.md): risk lenses, explicit coverage reconciliation, reachable source-to-sink evidence. Avoid the nested minimum-six-agent panel and unavailable private-store dependencies.

Adaptation: normally two fresh axes (correctness and intent/standards), plus at most one highest-risk specialist; one fresh combined reviewer for a tiny entirely mechanical change. Current supported model by default. Every actionable finding needs evidence and correction; agreement alone does not qualify. A final independent review remains mandatory after the last repair, including after exhausting the three-round budget.

The inspected upstream thread query caps threads/comments without pagination. This workflow requires pagination at both levels. Upstream's count rubric can classify one HIGH as "approve with nits"; this workflow never treats a confirmed actionable finding as clean. Neither upstream one-shot skill itself supplies the article's whole bounded outer loop; `/branch-closeout` does.

## Delivery, CI, and observation

- [Haacked: babysit-prs](https://github.com/haacked/dotfiles/blob/main/ai/skills/babysit-prs/SKILL.md) and [ci-monitor](https://github.com/haacked/dotfiles/blob/main/ai/skills/ci-monitor/SKILL.md): sweep/state separation, head-bound CI, bounded deadlines, empty-check and approval-held outcomes. Adapted to one explicitly invoked branch, not a scheduler over every open PR; no queue actions or reruns by default.
- [No-mistakes](https://github.com/kunchenguid/no-mistakes): independent session-free re-review, durable finding state, staged review/test/document/publish/CI flow. Relevant source contracts: [review/agents](https://github.com/kunchenguid/no-mistakes/blob/main/.agents/skills/pipeline-review-and-agents/SKILL.md), [branch/push safety](https://github.com/kunchenguid/no-mistakes/blob/main/.agents/skills/branch-sync-and-push-safety/SKILL.md), and [CI](https://github.com/kunchenguid/no-mistakes/blob/main/.agents/skills/ci-monitor/SKILL.md). This adaptation uses a fixed repair budget/deadline, normal immutable-SHA pushes only, and no automatic rebase or merge.
- [PostHog frontend QA](https://github.com/PostHog/posthog/blob/master/.agents/skills/qa-frontend/SKILL.md), [safety](https://github.com/PostHog/posthog/blob/master/.agents/skills/qa-frontend/references/safety-rules.md), and [evidence](https://github.com/PostHog/posthog/blob/master/.agents/skills/qa-frontend/references/evidence-and-output.md): independent expected outcomes, actual-stack identity, browser observation, honest intermittent/gap reports, and separate evidence-upload permission. Local evidence stays private/uncommitted by default.
- [StampHog PR approval-agent README](https://github.com/PostHog/posthog/blob/master/products/stamphog/packages/pr-approval-agent/README.md): fail-closed gates and separation of model evidence from deterministic verdict. This task is **draft handoff**, not an approval bot; no PostHog deny-list/size thresholds, stamp labels, auto-approval or merge actions.
- GitHub CLI contracts: [draft creation](https://cli.github.com/manual/gh_pr_create), [PR metadata](https://cli.github.com/manual/gh_pr_view), [checks](https://cli.github.com/manual/gh_pr_checks), [run listing](https://cli.github.com/manual/gh_run_list), and [run watching](https://cli.github.com/manual/gh_run_watch). `gh pr create --dry-run` may push; preparation therefore constructs artifacts/commands without invoking it. `gh pr checks` has pending exit code 8. Head-filtered run listing alone can miss synthetic-merge PR runs, so CI reconciles PR rollup and associated run metadata.

## Existing local contracts

`/pr-review` remains read-only and precision-first; `/pr-understand` remains explanatory. Neither is repurposed as a fixer. `/code-review` supplies the existing intent/standards distinction, but its discretionary smell baseline is not an auto-fix mandate. Existing `/open-pr` opens a generic browser creation form and does not implement the selected autonomous draft/exact-template contract; it remains unchanged.

Axion's current repository instructions require `<JIRA_KEY> - <concise summary>` and the complete `pull_request_template.md` in defined order. Its title CI accepts a broader regex; the stricter documented title wins. Current workflows and package scripts determine test coverage at invocation time, not this research snapshot. The existing `docs/2026-09-23-pr-review-non-mechanical-supplement.md` is discussion material, not an adopted policy; its exact-head finding ledger/human decision packet matches the user's requested review loop.
