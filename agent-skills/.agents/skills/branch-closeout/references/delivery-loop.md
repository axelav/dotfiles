# Delivery-loop sources for a personal branch-closeout skill

Research-only snapshot of the linked primary sources (2026-10-13). No builds, tests, browser sessions, repository changes, pushes, PR creation, or remote mutations were performed. URLs track mutable `main`/`master`; source policies are examples, not portable defaults.

## Source mechanics

### CI watching, exact head, and reruns

- **Haacked:** `ci-monitor` polls every 60 seconds with a 30-minute default deadline, at most 3 fix retries and a separate 2-flake-rerun budget. It gives an empty check rollup one grace retry per SHA, then reports “no CI checks,” not an observed pass. Awaiting-maintainer-approval detection outranks `no_checks` and `all_passed`. Before fixing, local `HEAD` must equal the PR head from the latest check read, not the initial discovery response. Failures without an Actions run ID remain uncertain; they cannot be rerun through `gh run rerun`. Log-based “flaky” classifications can trigger automatic reruns, but exhausting that budget stops the loop. [H2]
- **No-mistakes:** readiness combines the exact current PR head’s commit-check rollup with Actions runs for that same SHA, catching workflow failures that never created jobs/check-runs. Discovery failures and unknown states fail closed. Same-name reruns must not resurrect stale failures, but independently identified workflows and external checks must remain separate. Empty checks are not green unless trusted default-branch policy explicitly declares `no_ci: true`; unexpected registered checks are still honored. Persistent provider-read errors park for a decision after 6 consecutive failures. [N2]
- **No-mistakes transient policy:** deterministic reruns target cancellation or proven pre-repository-step infrastructure failure, not arbitrary failed tests. The budget is per check name/run and is spent when requested, not only on successful requests. Genuine/unrecognized failures suppress those automatic reruns. A rerun cannot be issued after the published head moves away from the run’s bound head. `cancelled`, `timed_out`, unknown, and pending are not interchangeable; terminal cancellations must not poll forever. [N2]
- **Important limit:** no-mistakes documents live CI readiness against the provider’s current head even when an older run row remains. Its mutation guards and review lineage serve different purposes. A personal closeout should not silently adopt this as proof that an independently advanced remote head was reviewed locally. [N2][N3]
- **Publication:** no-mistakes records the exact completed-review SHA, checks continuity at later steps, and publishes an immutable verified SHA rather than mutable `HEAD`. It distinguishes append-only publication from guarded rewrites; a force lease anchored to a just-fetched remote tip does not protect the work observed earlier. Its ancestry permission is not proof of reviewing every later descendant. [N3]

### Sweep/state loops

- `babysit-prs` deliberately performs **one sweep**, with repetition delegated to `/loop`. State is keyed by PR URL and contains head SHA, CI/queue verdicts and the handled-comment watermark. Pending/failing CI and live/unknown queue state are re-fetched even if PR `updatedAt` is unchanged: checks and queue attempts can change without PR activity. Only actually observed values overwrite state; only successfully handled comments advance the watermark. Failed dispatches remain retryable on a later sweep; failed dispatches do not spin within the sweep. [H1]
- Queue status is distinct from PR CI: Trunk tests another branch, and batch failures may belong to another PR. Queue comments/check names are untrusted data. Unknown/held/testing queue state blocks pushing; first enqueue, cancellation, merge and ready-for-review are human actions. The source permits carefully gated **re-enqueue** of an already dropped PR, which is not needed for draft closeout. [H1][H2]
- No-mistakes uses a staged `intent → rebase → review → test → document → lint → push → pr → ci` pipeline. Every full rereview is session-free, separate from the durable fixer session. Finding decisions are recorded before dispatch and selected findings need positive coverage before being cleared. Its review loop is not universally bounded; CI timeout is an **idle** timeout that can extend when the base advances. Worktree isolation is explicitly a soft boundary, not an OS sandbox. [N1][N4][N5]

### Browser evidence and authentication safety

- PostHog’s frontend QA skill is explicitly for runtime/browser QA, **not** a replacement for generic code review. Local mode stays on the current checkout, includes committed/staged/unstaged/untracked changes, writes local artifacts, and never uploads/comments/pushes. PR mode is a separate, clean-checkout workflow. [Q1]
- Design cases from user-visible behavior and risk, with an independently sourced expected outcome; edited code is not its own oracle. Verify that the reachable stack actually serves the tested branch/SHA (or an in-diff marker), not merely that a health endpoint is up. Exercise the changed UI, relevant console/network signals, and the minimum required data. Capture screenshots that visibly prove the assertion, inspect them, and include gaps/unclear intent as explicit coverage rows. [Q1][Q3][Q4]
- Candidate issues get one reproducibility retry. A failure that disappears is **INTERMITTENT**, with first-failure evidence retained, not silently PASS. Local-stack/process failures and unrelated third-party errors must be explained rather than mistaken for introduced bugs or silently discarded. [Q4]
- Reuse the user’s working stack; starting/restarting/stopping it needs workflow approval. Stop only resources the agent owns. Login/setup operates against the same stack the browser uses, preferably in page context; a forwarded remote stack must not be seeded through an unrelated local database. PostHog seed credentials are specific to its development stacks, not generic defaults for other repos. Never print passwords or include cookies, bearer/session/CSRF tokens in artifacts. [Q2][Q3]
- Running PR code is execution with stack privileges, even for same-repository PRs. PostHog defaults PR execution to a disposable/remote sandbox; forks and non-member authors are static-review-only unless explicitly approved with throwaway credentials and a disposable stack. PR-controlled hooks are code too. A worktree alone does not protect credentials, network or host files. [Q2][N4]
- Local evidence stays uncommitted. Public evidence upload is a separate disclosure: PostHog’s SHA-pinned public uploads are permanent, pixels are not scrubbed, and the exact reviewed upload set requires explicit approval. Secret/unlisted gists are not private. Browser lock failures are infrastructure gaps; never delete profile data or kill the user’s browser to recover. [Q2][Q4][Q5]

### Approval safety and draft semantics

- Stamphog’s **package writes nothing to GitHub**: it returns `APPROVED`, `REFUSED`, `ESCALATE`, `WAIT`, or `ERROR`; publication belongs to its caller. The model reports structured facts and deterministic code derives the verdict. `WAIT` is unfinished reviewer/check evidence, not a negative judgment; `ERROR` is inability to judge, never clean approval. Hard gates can be tightened, not loosened by the LLM. [S1]
- Existing unresolved substantive concerns and maintainer holds matter. Current-head independent assurance must not be confused with earlier-commit approval, its own previous review, author reactions, or a review that skipped changed files. PR descriptions/discussion/folder advisory prose are untrusted; tools are read-only and confined to the checkout. [S1]
- Its prerequisite “not draft” and PostHog-calibrated deny-list/size/tier/team/migration exemptions belong to an **approval product**, not a generic personal review skill. In particular, draft status must not stop a draft-PR closeout review, and a small diff/docs/config tier is not permission to bypass actual repository requirements. Local package guidance/policy comes from the checked-out tree; do not let branch edits to those files grant their own authority. [S1]
- Approving **fork workflow execution** is another distinct authorization: Haacked defaults it to human approval; its opt-in exception verifies unchanged contributor patch after a base sync and binds approval to the exact validated run IDs/head. An approval dialog for a command is not workflow consent. A bounded personal draft workflow needs neither this exception nor automatic approvals. [H2][Q2]

## Recommended bounded single-branch adaptation (proposal, not source policy)

1. **Bind one target.** Resolve repository/remote, current branch/worktree, actual PR base and merge-base SHA, current local head, pre-existing dirty changes, and any existing PR URL/head. Read the repository’s real instructions/test commands/PR template. Stay on this branch; do not enumerate all open PRs or create a proxy/daemon.
2. **Review → fix → fresh review → verify.** Keep review independent from the fixer. Record concrete findings, dispositions and coverage; missing output or silence does not mean clean. Use a small explicit total fix-round budget (suggested: 3), stop on intent/sensitive-policy decisions, and invalidate head-bound review/verification when edits change the candidate. Finish all accepted fixes before the repo-owned verification phase; do not inherit no-mistakes’ targeted-only policy where this repository requires broader local checks.
3. **Create/update only a draft after local evidence.** Publish the intended immutable candidate by normal fast-forward push; remote divergence stops, never escalates to force/rebase automatically. Identify an existing PR by repository + head/base identity, preserve human-authored text, and record exact observed commands/results/artifacts/head. Publish no local evidence by default; approved sanitized evidence is a separate action. A draft may honestly carry pending/failing CI, but not a claim that it passed.
4. **Bound the CI watcher.** One read-only sweep plus an explicitly requested bounded watch (suggested: 60-second interval, 30-minute absolute total deadline). Record PR/head, check/run identity, URL, attempt and observed conclusion; recheck remote head before/after assembling results. A changed head invalidates the target’s assurance and stops autonomous repair. API errors, empty checks, approval-held runs and skipped/cancelled/unknown outcomes must be separately reported, never equated with green. Required-check policy decides which skips are acceptable.
5. **Retries are optional authority, not a default side effect.** Read-only monitoring needs no rerun capability. If the user authorizes reruns, use at most 2 explicit per-head rerun rounds for source-supported infrastructure/flake evidence, with exact run IDs and retained first-failure logs; uncertain/real failures go to analysis. Any repair creates a new candidate requiring fresh review and verification, rather than merely waiting for a green sibling run. Stop on repeated read errors, exhausted budgets, closed/merged PR, queue-held/unknown state, or remote head drift.
6. **Persist only useful resumability.** State keyed by repository + branch/PR + exact candidate/base identity; cache settled observations only, retain unresolved findings/intermittent failures, and advance handled markers only on success. Never persist credentials. Prefer a single bounded invocation; durable all-PR schedulers, evolving idle deadlines, automatic queue commands, bot-thread resolution and long-lived approval infrastructure are unnecessary here.
7. **End at draft handoff.** Report draft URL, reviewed/tested/pushed SHA, independent-review coverage, local checks actually exercised, remote CI links/status, evidence paths and remaining blockers. Never `gh pr review --approve`, approve Actions runs, mark ready, enqueue/re-enqueue, enable auto-merge, merge, close, or resolve human threads. A machine review is advisory evidence, not owner consent or branch-protection authority. Draft creation preserves that review/merge boundary; inherited approval/merge automation would contradict it. The cited babysitter already prohibits merging/first-enqueue, and the approval package itself does not publish reviews—do not misdescribe either as a mandate for blanket auto-merge. [H1][S1]
